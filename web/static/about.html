About the model

Food–Drug ML model with SHAP — a three-class interaction predictor built from the FHDI gold-standard dataset, molecular descriptors, grouped-drug validation, explainability, and a safety-first inference layer.

Abstract

The system predicts the effect of pairing a drug with a food compound in one of three classes: avoid together, beneficial / take with food, or non-significant. Each molecule is represented by 60 MOE descriptors from RDKit/PyBioMed. Drug–compound pairs are expanded into 3,780 pairwise features (descriptor products, sums, absolute differences and ratios), then reduced to 18 features by variance, correlation, LASSO and permutation selection. Five classifiers are tuned on a validation partition: XGBoost, LightGBM, RandomForest, ExtraTrees and a multi-layer perceptron. Models are evaluated with a drug-grouped split (Split G) for honest generalization to unseen drugs, plus a random split (Split R) for paper comparability. One LightGBM model is served, with the majority non-significant class capped in training to trade a little validation macro-F1 for higher avoid-class recall. Drug and food names are resolved to SMILES by the local database, then Gemini, then PubChem, and every answer is validated with RDKit. The model is wrapped in a rule/evidence inference layer, abstains below a validation-selected 0.77 confidence threshold, and returns TreeSHAP contributions for every feature and every class.

How a prediction is made

  1. Input resolution. Drug and food names, IDs or SMILES are normalized and matched against curated tables. Unknown names are resolved to a canonical SMILES by Gemini, then PubChem, and every structure is validated with RDKit. The Gemini key stays server-side in .env and is never sent to the browser. Food names are expanded to marker compounds (for example grapefruit → naringin/bergamottin).
  2. Clinical rule layer. Well-established interactions (warfarin + grapefruit, simvastatin + grapefruit, metronidazole + alcohol, tetracyclines + calcium, MAO inhibitors + tyramine) short-circuit to a conservative verdict with a stated reason.
  3. Exact-pair dataset evidence. If the labelled dataset contains a non-synthetic annotation for the exact drug–compound pair, that label is used and shown as evidence.
  4. ML scoring. Otherwise the pair is featurized and the trained LightGBM model returns three class probabilities. The UI displays the winning class, the probability bars, applicability-domain similarity and latency.
  5. Abstention. If the calibrated top probability is below the validation-selected 0.77, or either molecule is outside the applicability domain, or the compound is inorganic, the system refuses to give a confident verdict and asks the user to consult a pharmacist.

Positive-class limitation

The current specific-pair label set contains only 24 beneficial examples, with 8 available to train the served drug-grouped model. A held-out score cannot establish 90% reliability for this class. Exact annotated pairs are returned as dataset evidence; model-only positive signals remain provisional and are not medication advice. More independently curated positive pairs are required before claiming high positive-class accuracy.

Architecture

Backend — FastAPI

  • One lazily built, thread-safe engine; the frozen model is loaded once and its SHAP explainer is pre-warmed.
  • POST /api/predict — verdict, probabilities, resolution, SHAP, matched compounds, latency.
  • GET /api/suggest — autocomplete over 1,359 drugs and 4,877 compounds.
  • GET /api/health, GET /api/meta — readiness, model metadata, resolver status and rules.
  • GET /, /predict, /about — landing, predictor, documentation pages.

Frontend — vanilla HTML/CSS/JS

  • Landing page, predictor page and this about page; no framework or build step.
  • Fetch API with debounced autocomplete and AbortController for stale requests.
  • XSS-safe DOM rendering via textContent; accessible labels and ARIA states.
  • Probability bars, evidence/rule badges, calibrated confidence, resolution source, domain similarity, per-class SHAP and candidate compounds.

Techniques used

Molecular representation

RDKit parses and canonicalizes SMILES. PyBioMed computes 60 MOE descriptors per molecule; inorganic or metal-containing compounds are refused.

Pairwise feature algebra

For 60 descriptors: 3,600 products, 60 sums, 60 absolute differences and 60 ratios, giving 3,780 candidate features that encode both molecules and their complementarity.

Tanimoto / Morgan fingerprints

Nearest-neighbour Tanimoto similarity on 2,048-bit Morgan fingerprints powers the applicability domain. It is also used during cleaning to remove near-duplicate compounds.

Feature selection

Variance filter, Pearson correlation pruning (0.75), LASSO, stability selection and permutation importance reduce 3,780 features to 18.

Models & tuning

XGBoost, LightGBM, RandomForest, ExtraTrees and MLP, tuned with RandomizedSearchCV on a validation partition. Balanced class weights and 0.5 weights for weak synthetic pairs address the severe imbalance; the deployed model additionally caps the non-significant class at 2:1 in training.

Grouped validation

Split G holds out whole drugs to measure generalization to unseen drugs. Split F holds out compounds, Split D holds out both, and Split R is a random reference. GroupKFold is used inside training.

SHAP explanations

TreeSHAP explains each class on the test partition and, at prediction time, returns signed contributions for all 18 features in all three classes. The predicted class is expanded; the other two are available on demand.

Calibration & abstention

Temperature scaling is fitted on Split G validation. The acceptance threshold is the lowest validation threshold whose accepted error is at most 20% (currently 0.77). Below the threshold the predicted class is shown with its calibrated confidence and an abstention note; out-of-domain inputs are refused rather than guessed.

One label policy

Pair-level labels

Labels only the compounds named by the interaction text, curated marker compounds of a named food, or food-specific compounds. Corrected semantics treat warning-style “Positive” annotations as avoid. 444 labelled drugs, 21,042 pairs, classes 4,898 avoid / 24 beneficial / 16,120 non-significant.

Why one model

An earlier “paper-like” mode copied one drug-level label onto every sampled compound. It produced large, easy numbers from label leakage rather than chemistry, so it was removed from the pipeline and serving path. There is now a single model and a single meaning for each class.

Deployed single model (class-2 cap 2:1)

The served artifact is a single LightGBM model. In training only, the dominant non-significant class is capped at twice the avoid class; validation and test keep the real distribution. On validation this costs 0.016 macro-F1 (0.4465 → 0.4304) and gains 0.090 avoid-class recall (0.312 → 0.402) — a safety trade-off, not a metric improvement. Limitations & safety

  • Descriptor-only features cannot identify a named drug, so known clinical pairs rely on the rule and evidence layers. The ML model handles unseen, chemically plausible pairs.
  • Avoid-class recall on unseen drugs is about 0.39 even after the safety-oriented class cap; most avoid pairs are still missed, so abstention and the rule layer matter.
  • Class 1 has only 24 real pairs (one in the Split G test set); its metrics are not evidence of learning.
  • Double-cold generalization is weak (MCC −0.07); the system does not claim broad chemical generalization.
  • Name resolution can fail or mis-resolve mixtures and ambiguous names. Every response shows the resolved SMILES and its source so the structure can be checked.
  • This is a research tool. It does not replace clinical judgement; always confirm with a physician or pharmacist.
